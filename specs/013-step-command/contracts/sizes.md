# Contract: `sizes.json`, `sizes.tsv` and `sizes.py`

`.apm/skills/feat/sizes.json` stays the one source and keeps shipping.

## `sizes.json` changes

- `fix.rows` 4a–4d gain `"lens": "7a"` … `"7d"` (the code reviewer lens
  each row runs). `feat` rows carry no `lens` key: a feat reviewer row's
  lens is its id.
- `fix.groups` (new), today's `/fix` prose as data:

  ```json
  "groups": {
    "4": {
      "small":  [["4a", "4b", "4d"]],
      "medium": [["4a", "4b"]],
      "large":  [["4a"], ["4b"]],
      "performance": {
        "small":  [["4a", "4b", "4d"]],
        "medium": [["4a", "4b", "4c"]],
        "large":  [["4a"], ["4b"], ["4c"]]
      }
    }
  }
  ```

  `performance` is the variant for an assessment with `Performance bug:
  yes`; a size it does not list falls back to the default groups.
- `feat.groups` unchanged. The order of a size's groups is the spawn
  order; on `/feat` phase 7 a group made of `7e` alone runs after the
  others, with 7d's cuts (a rule of `step.sh`, not of the data).

## `sizes.py` validation

- `only_keys`: `fix` accepts `rows` and `groups`; a row accepts `lens`
  (`fix` only, one of `7a`–`7e`, required on `fix` rows whose agent is
  `feat-code-reviewer`).
- `check_groups(groups, rows, strict)`: `feat` stays strict (every phase
  with two or more rows has groups; each size lists each row once). `fix`
  is loose: each listed id is a row of that phase, no id twice in one
  size's list, every size present; the `performance` object, when present,
  follows the same rules but may leave a size out (the default groups
  apply).

## `sizes.tsv`

Generated, tab-separated, LF, no trailing tab. Comment lines start with
`#`. One line per row and size, then one line per group, in source order:

```
# Generated by docs/diagrams/sizes.py from sizes.json; edit that and run `mise run diagrams`.
# In an install (no sizes.py), tune a row by editing its `row` line and every `group` line that names it:
# each group line carries its own model and effort (the strongest of its rows), and groups are what review phases spawn.
# row	skill	row	agent	lens	size	model	effort
# group	skill	phase	size	variant	rows	lenses	model	effort
row	feat	2	feat-specifier	-	small	sonnet	medium
…
row	fix	4a	feat-code-reviewer	7a	small	sonnet	medium
…
group	feat	4	small	default	4a+4b+4c	4a+4b+4c	sonnet	medium
group	feat	7	medium	default	7e	7e	sonnet	medium
group	fix	4	medium	performance	4a+4b+4c	7a+7b+7c	opus	medium
…
```

- `lens`: the row's lens (`fix`), its id for a `feat` reviewer row (4x, 7x),
  else `-`.
- `rows`/`lenses`: the group's ids and lenses joined with `+`.
- `model`/`effort`: the strongest among the group's rows for that size
  (`strongest()`, as `models.svg` uses it).
- Phases with one row have no `group` lines; `step.sh` spawns the row.
- Tuning: in this repo `sizes.tsv` is never edited by hand (`--check`
  fails on drift). An install has no `sizes.py`: the header comment above
  and `docs/usage.md`, Tuning, say to edit the `row` line and every `group`
  line naming that row, since editing the row alone leaves the groups'
  precomputed model and effort as they were.

`step.sh` reads it with `while IFS=$'\t' read -r …`, skipping `#` lines;
a missing file, a missing row, or a `Size` with no line is `step: error:
sizes.tsv has no <row> <size>`.

## Targets

`sizes.py` writes and checks (`--check`):

| Target | Kind |
| ------ | ---- |
| `.apm/skills/feat/sizes.tsv` | whole file (new) |
| `docs/workflow.md` `feat-matrix`, `fix-matrix`, `agents-table` | marked regions (unchanged) |
| `.apm/skills/brief/SKILL.md` `brief-review` | inline region (unchanged) |
| `.apm/skills/feat/SKILL.md` `feat-table`, `.apm/skills/fix/SKILL.md` `fix-table` | removed with the tables |

`--check` fails on a whole-file target that differs (`sizes.tsv is stale:
run mise run diagrams`) as it does on a marked region. `--d2` unchanged.

## Tests (`tests/sizes/`)

- Fixtures: `feat-SKILL.md` and `fix-SKILL.md` leave (no table to
  regenerate); `fixtures/sizes.json` gains the `fix` groups and lenses.
- Expected: `sizes.tsv` added; the regenerate case writes it into the
  scratch root and compares; a stale `sizes.tsv` makes `--check` fail with
  its line; a hand edit inside it is overwritten.
- Validation cases: a `fix` group naming a row of another phase, an id
  twice in one size, a bad `lens`, a `performance` object missing a size
  (allowed), a `feat` group missing a row (still refused).
